## Overall assessment

The candidate is a coherent prospective implementation of the seven-operation Workbook write boundary: typed staging, Workbook-view/ID resolution, per-Worksheet capability checks, FIFO serialization, Journal/Snapshot rollback paths, commit-buffered events, and queued-work cancellation on disposal. Its dependency graph journal records both direct and inverse edge state plus dirty bits; the formula change cleanly places graph registration outside the parser/extraction catch, so a graph-write exception can reach the transaction rollback path while the existing extraction warning behavior remains.

The source is not ready to integrate on this review alone. Two material gaps remain:

1. The candidate's EventBus `once` wrapper retains the base implementation's remove-after-callback behavior. In isolated Workbook dispatch, a throwing one-shot handler is caught outside that wrapper before `off()` executes; nested emission can also see the wrapper before it is removed. This conflicts with the accepted PKG-02F correction evidence and would regress it if the candidate EventBus file replaced the corrected working version. The specific correction was intentionally absent from PKG-18 and needs to be reconciled into any integration candidate.
2. The candidate adds/promotes public Workbook write APIs and identity/status methods while authoritative D0-06 still requires definition of the new Workbook mutation API and compatibility/versioning policy. These signatures and their lifecycle semantics need the designated owner decision; candidate reconstruction and tests are not that approval.

Post-disposal EventBus subscription behavior remains unresolved by this source-only lane and is assigned to Lane C. The candidate permits `on()` after `Workbook.dispose()`; that call can activate a bridge even though the Workbook's continuation guard prevents publication. Lane C must establish the applicable lifecycle contract and report whether that is a supported defect or an unsupported historical expectation.

## Cross-cutting contract and lifecycle observations

- **Ownership:** `Workbook.create()` and `attachDevImportSheet()` retain the capability returned by Worksheet adoption; every staged operation resolves to this Workbook's sheet identity before applying. Raw adopted Worksheet setters remain wrapped and reject outside the temporary capability scope. No generic add-sheet path is enabled. The dev-import attachment path's comment should be reconciled: it says attached sheets are not adopted, while this candidate now adopts them after import-time population.
- **Journal/Snapshot:** Journal stores first-touch cell and sparse dimension before-images and graph deltas; Snapshot captures cell records, explicit dimensions, and graph state and restores via a separate path. PKG-18's reports describe differential tests. Neither source review nor the selected evidence closes unenumerated D2-11 side effects, StyleCache exact-reference residuals, or all restoration-failure cuts.
- **Fault propagation:** Worksheet mutator fault hooks occur after cell-record writes and around dimension writes. Graph mutation faults propagate after the formula extraction `try/catch`. Failed mutation attempts restore Worksheet and graph state before clearing batches; failed restoration records `recovery-required`. A restoration failure may leave partially restored internal state by definition, and the status rejects later mutations rather than claiming repair.
- **Queue/disposal:** queued work is rejected and an active async callback is raced against cancellation; the staging context is revoked and apply rechecks disposed state. The documented direct/indirect FIFO self-await limitation remains. `dispose()` removes existing EventBus subscriptions/bridges and postpones Pivot cleanup until the queue drains. It does not prevent a later call to the exposed EventBus `on()` from registering again; Lane C owns the contract classification of that case.
- **Publication:** events are retained in staged order and published only after the commit point. Worksheet listener exceptions are isolated; Workbook dispatch uses isolated snapshots and stops on disposal. Dimension events are emitted as explicit Workbook events after the corresponding buffered Worksheet event. D5-05 Application forwarding is absent; D5-01's Option C remains pending owner approval, and this source review does not promote it.
- **Formula/Pivot/API scope:** the candidate does not add formula syntax, origin/rebasing, Pivot lifecycle, comment deletion, Application events, or a new mutation kind. The seven write APIs themselves are the proposed Workbook contract surface and remain subject to D0-06/owner approval.

## Disposition

**Independent source review: completed with a correction requirement and owner/API dependencies.** The candidate's transaction mechanism is technically coherent within its bounded operation/state inventory, but it is not cleanly integration-ready because EventBus `once` would regress the accepted PKG-02F behavior and the proposed public mutation/API surface still depends on D0-06 owner decisions. Lane C's post-disposal subscription result and Lane D's unfiltered verification remain necessary inputs to PKG-19R.

No historical source ownership is inferred. No candidate or shared source was changed. D0 remains **PROPOSED**, D1–D7 remain **PENDING**, and overall CS-002D4-R1 acceptance remains **WITHHELD**.
