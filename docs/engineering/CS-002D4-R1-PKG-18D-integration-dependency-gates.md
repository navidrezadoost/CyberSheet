## Dependency distinctions

- **Evidence can precede approval.** Existing characterization and proposals can be reviewed now; they cannot promote a disposition or select a contract by implication.
- **Contract approval precedes dependent implementation.** Formula grammar/origin, Workbook Pivot lifecycle, comment deletion, D3-06, Error DTO, D5-01/05, and D7-05 require their scoped owner decisions before any dependent behavior change is authorized.
- **Not every Pivot integration assertion needs every Pivot decision.** PKG-16D identifies numeric snapshot/source-refresh migration cases that can be separated from stale-formula assertions (D3-06) and Error-valued snapshot assertions (Error DTO). The lifecycle facade itself remains owner-decision-dependent.
- **A decision does not authorize a patch.** Each selected contract change still needs a separate bounded implementation directive, acceptance criteria, and verification scope.
- **Release readiness is conjunctive.** Technical evidence, reachable supported integration routes, contract authority, implementation authorization, and unresolved residual disposition must all be reviewed together; none can stand in for another.
