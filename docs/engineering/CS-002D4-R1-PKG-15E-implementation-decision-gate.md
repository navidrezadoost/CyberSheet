## Readiness rule

An approval removes only the named contract blocker. It does not authorize production changes by itself. Before implementation, record the decision owner and authority basis, exact approved wording and scope, required concurrence, effective date, and a separate bounded authorization with acceptance criteria. Technical verification may proceed on currently supported behavior while these decisions remain pending.

The priority order favors formula compatibility and transaction side effects because they affect supported Core correctness and can be investigated without enabling new public APIs. Pivot lifecycle and comment deletion remain owner-gated. Event and merged-read decisions remain separately scoped. Overall CS-002D4-R1 acceptance remains **WITHHELD**.
