# CS-002D4.4 — Workbook Manifest and Migration

**Status:** Design only · **Priority:** P0 architecture dependency  
**Predecessors:** CS-002D4.1 identity (O1 normative), CS-002D4.2 typed formula binding (accepted/closed)  
**Parent:** [CS-002D.4 production integration design](../architecture/CS-002D4-production-integration-design.md)  
**Reported:** 2026-10-17  
**Implementation:** Not authorized in this ticket

## 1. Goal and decisions

Define a versioned workbook persistence envelope around existing worksheet snapshots. The manifest owns workbook-level worksheet identity, names, order, active sheet, and embedded CSEX payload framing. It does not replace the worksheet codec or serialize derived graph adjacency.

**Normative decisions for the implementation specification:**

1. Preserve three independent versions: workbook `manifestVersion`, each embedded CSEX binary `payloadVersion`, and the decoded `WorksheetSnapshot.version` object version. They are not interchangeable.
2. Preserve D4.1 workbook-owned opaque `WorksheetId`s across whole-workbook save/restore and clone into a fresh owner. Persist `nextSheetSequence` greater than every issued ID; never reuse a deleted ID in that workbook lineage.
3. Preserve exact formula text across rename and save/load. Persist a compact identity sidecar for each qualified reference occurrence: formula-owner sheet ID/address, stable occurrence ordinal, source-formula digest, and target sheet ID. These records preserve binding identity; they are not dependency edges. Rebuild local and cross-sheet dependency graphs from formula text plus these bindings after every sheet has been staged.
4. Deleting a referenced sheet leaves its persisted target ID absent. That reference evaluates to `#REF!`; creating another sheet with the deleted sheet's former name does not capture it. A fresh formula edit may bind to the new sheet by its current name.
5. Decode and validate the complete manifest and all worksheet payloads into isolated temporary state before publishing or replacing any live workbook. Corruption or unsupported versions reject atomically.
6. Legacy loose worksheet snapshots have no reliable workbook identity. Import them through an explicit migration/adoption path that allocates fresh IDs and records migration provenance; do not infer that a process-local `ws-*` ID is durable.

The formula-binding sidecar is needed because formula text alone cannot preserve identity after a target sheet is renamed or deleted and a different sheet later takes the old name. It stores stable reference targets, not graph edges, caches, or scheduling order. Any binding sidecar row whose formula digest/occurrence no longer matches is rejected as corrupt or migrated through a defined upgrader; it must not be applied to a different reference token.

### Current omission inventory

The core workbook has no production-level manifest codec or whole-workbook snapshot/restore API. The current worksheet snapshot object excludes filters, conditional-formatting rules, and formula-engine reference. In addition, CSEX's five encoded sections do not serialize the object-level optional dimensions, row heights, column widths, row styles, column styles, or drawings even though `extractSnapshot()` returns those fields. CSEX does encode cell values/formulas/styles/comments/icons/spill metadata, merges, visibility, local DAG edges, and volatiles. This is a source-level fidelity gap, not an assumption that all omitted values are empty.

At workbook scope, current `Workbook` owns pivots/registries/snapshots, indexes, slicers through pivot state, event bridges, and style cache, but none is part of a workbook manifest. The experimental prototype persists only worksheets and formula-binding-derived models. CSEX has no sections for chart objects, named ranges, workbook calculation settings, protection metadata, data validation rules, conditional formatting, filters, workbook styles/theme, or these pivot subsystems. The serialized `FileOperations` shape mentions named ranges and conditional formats but is not evidence they round-trip through the core codec.

**Compatibility policy:** first production manifest is explicitly a **calculation-state manifest**, not a claim of full UI/workbook fidelity. Every omitted feature must be either (a) added to a versioned manifest/payload section before claiming fidelity, or (b) rejected on export when non-default state would otherwise be silently lost, or (c) clearly reported as unsupported/lossy by an explicitly requested export mode. Silent loss is not acceptable.

## 3. Normative manifest schema (proposed wire contract)

The external envelope is a binary framing format; JSON below specifies decoded logical fields. Fixed-width fields are little-endian. UTF-8 names and IDs use explicit unsigned byte lengths. Every arithmetic operation on counts/offsets/lengths is checked for safe integer overflow and buffer bounds before allocation or slicing.

```ts
interface WorkbookManifestV1 {
  format: 'cybersheet-workbook';
  manifestVersion: 1;
  workbookId: string;                 // stable document identity; opaque
  nextSheetSequence: number;          // persisted allocator high-water mark; ID text stays opaque
  activeSheetId: WorksheetId;
  order: WorksheetId[];               // exact visible worksheet order
  sheets: Array<{
    id: WorksheetId;
    name: string;
    payloadVersion: number;             // embedded CSEX binary version; accepted only with a decoder/upgrader
    payloadLength: number;            // exact bytes in payload
    payloadCrc32?: number;            // envelope integrity over exact payload bytes
    payload: Uint8Array;
  }>;
  formulaBindings: Array<{
    formulaSheetId: WorksheetId;
    row: number;                      // one-based
    col: number;                      // one-based
    formulaDigest: string;            // lowercase SHA-256 of exact UTF-8 formula text bytes
    occurrence: number;               // zero-based typed-reference occurrence in parse order
    targetSheetId: WorksheetId | null; // null is a persisted unresolved qualified target
  }>;
  provenance?: {
    source: 'native' | 'legacy-worksheet-import' | 'clone' | 'import';
    sourceManifestVersion?: number;
  };
}
```

`workbookId` is a document lineage token, not an authority for worksheet IDs. Whole-workbook restore and clone preserve `workbookId` and all sheet IDs while creating a fresh in-memory owner. Importing a sheet into another workbook keeps the target `workbookId`, allocates a fresh target `WorksheetId`, and rewrites the imported sheet's references according to explicit import mapping. If product requirements require “Save As” to fork workbook lineage, that operation must be named and specified separately; it is not ordinary restore/clone.

### Binary framing

The initial envelope frame is: distinct fixed magic `CSEW`, envelope format tag `cybersheet-workbook`, `manifestVersion`, flags, total byte length, manifest metadata length, sheet count, and a CRC32 covering the complete envelope with its checksum field zeroed. The metadata block contains workbook ID, next sequence, active ID, order, formula-binding rows, and a per-sheet directory `(id, name, payloadVersion, payloadLength, payloadCrc32, payloadOffset)`. Payload blobs follow contiguously in `order` sequence. The directory offsets and lengths must exactly partition the payload region: no overlap, gaps, integer overflow, truncation, or trailing unaccounted bytes. `payloadVersion` is the CSEX binary header version, not `WorksheetSnapshot.version`.

The exact byte widths and string encoding are implementation-spec details, but the acceptance invariant is fixed: a reader can validate the outer framing and per-sheet payload framing before invoking any worksheet decoder. It must never infer a payload boundary by decoding until a section happens to end.

### Referential invariants

- `order` has exactly one occurrence of every sheet ID in `sheets`; no missing or extra IDs.
- Every sheet ID is valid, unique, and conforms to the selected production allocator format. D4.1's format is opaque to consumers; sequence validation belongs to the allocator/parser, not arbitrary string arithmetic outside it.
- Names are valid under worksheet naming rules and unique under case-insensitive normalization.
- `activeSheetId` is present in `sheets`; at least one sheet exists.
- `nextSheetSequence` is a positive integer greater than the maximum issued sequence in this workbook lineage. IDs are never reused after deletion.
- Every formula-binding row points to an existing formula-owner sheet, an in-bounds formula cell, and a parsed reference occurrence in that formula. A non-null target ID must be well-formed for this workbook lineage; it may be absent from the current sheet set only to preserve a deleted-sheet reference. A null target ID records a syntactically valid qualifier that was unresolved at binding time. Both forms yield `#REF!` and must not be remapped by display name on restore.
- Formula-binding rows are unique by `(formulaSheetId,row,col,occurrence)` and their formula digest must match the exact cell formula text.
- No decoded graph edges are authoritative. Local/qualified dependencies and range watchers are rebuilt from formula ASTs plus the validated binding sidecar after all sheets and IDs exist.

## 4. Migration and compatibility decision matrix

| Input / operation | Accepted? | Identity / migration rule | Fidelity and failure behavior |
| --- | --- | --- | --- |
| Native manifest v1 embedding CSEX v1 | Yes | Preserve persisted workbook/sheet IDs. Decode CSEX v1, apply registered worksheet-object upgrader, then stage. | CSEX v1 has no CRC. Outer manifest CRC and payload-length/framing checks still apply. Reject malformed binary before exposure. |
| Native manifest v1 embedding CSEX v2 | Yes | Preserve persisted IDs; verify per-payload CRC when present and CSEX v2 CRC when flagged; decode/upgrader axes independently. | Current v2 header checksum flag may be absent; manifest-level CRC is required for native new writes. |
| Manifest with unsupported `manifestVersion` | No | No implicit downgrade or “best effort” parse. | Reject before staging with `UnsupportedManifestVersion`; live workbook unchanged. |
| Manifest with unsupported `payloadVersion` or missing upgrader | No | Do not allocate/publish sheets. | Reject with sheet ID/name and version diagnostic; live workbook unchanged. |
| Legacy loose `WorksheetSnapshot` object(s), no workbook manifest | Yes, explicit legacy import only | Allocate fresh workbook ID and fresh sheet IDs in listed input order. Use caller-supplied names or deterministic `Sheet1…`; record `legacy-worksheet-import` provenance. | No cross-sheet identity can be recovered reliably. Qualified references resolve by names only if unambiguous during this one-time import; unknown qualifiers remain broken `#REF!`. Do not trust legacy `ws-*` IDs as persistent IDs. |
| Legacy standalone CSEX v1/v2 payload(s), no manifest | Yes, explicit legacy import only | Same as above after CSEX decode. A single payload defaults to `Sheet1`; multiple payloads require caller-supplied ordered names or deterministic names. | Do not auto-merge into a live workbook; import path allocates new IDs and performs validation first. |
| Duplicate sheet IDs, malformed IDs, duplicate names (case-insensitive), invalid order, active ID absent | No | Reject entire manifest; never pick first/last or rewrite IDs silently. | `InvalidWorkbookManifest` with offending field; no state becomes observable. |
| `nextSheetSequence` not greater than IDs/high-water mark | No | Reject rather than risk future ID collision. | `InvalidWorkbookManifest`; IDs are never renumbered during restore. |
| Duplicate or dangling formula-binding keys, digest mismatch, owner not formula cell | No | Reject manifest or run an explicit versioned migrator that re-parses/rebinds all refs. | Whole-workbook clone / restore into fresh owner | Yes | Preserve workbook ID, worksheet IDs, names, order, active ID, and qualified target IDs. Allocate fresh Worksheet objects, stores, graphs, caches, scheduler, event subscriptions, and indexes. | Must not share mutable objects, events, caches, or graph state with source workbook. Recompute under D4.5 before marking restored calculation state current. |
| Sheet import into existing/different workbook | Yes, explicit operation | Allocate fresh ID from target allocator; preserve display name only if no collision, otherwise require an explicit new name. Remap references inside imported sheets using import map; references to non-imported source sheets remain unresolved unless user supplies mapping. | Never carry foreign IDs into target owner. Reject name collision absent explicit resolution. |
| Invalid/truncated/corrupt payload or checksum mismatch | No | Decode all payloads in isolated staging. | Reject complete workbook before exposure; preserve prior live workbook and subscriptions unchanged. |
| Worksheet feature omitted by CSEX codec | Not silently accepted for lossless save | See §2 omission inventory. | Lossless mode rejects non-default unsupported state; explicitly lossy export reports each omitted feature and requires caller opt-in. |

Legacy migration is a one-time interpretation boundary. It must not fabricate durable identity from object identity, `ws-*`, map iteration after the fact, or filenames. If the legacy container has no order metadata, caller order is the migration order and is captured in manifest `order` thereafter.

## 5. Rename, deletion, and reference persistence

D4.2 selected separate parsed source references and ID-bound runtime references. This manifest therefore stores `formulaBindings` as identity metadata while continuing to store exact formula text in the existing cell payload.

- **Rename:** update the manifest sheet's name only. Formula text and `formulaBindings.targetSheetId` are unchanged. The formula continues to identify the same sheet ID after reload; formula text rendering preserves the source spelling until a separately authorized reference-rewrite feature is designed. New formula parsing resolves the current name through the case-insensitive directory.
- **Delete target sheet:** remove the sheet record/order entry and active selection falls back to a remaining sheet. Retain binding sidecar rows in referring formulas with the now-absent target ID. Such a reference evaluates as `#REF!`; no name-based fallback is permitted. The formula text may still display its original qualifier. If the user later edits that formula, normal binding by the then-current name applies.
- **Delete formula owner sheet:** remove its formula-binding rows with that owner; no dangling owner records are permitted.
- **Save and restore:** the source formula text is decoded first; parser occurrence ordinals and digest are checked; the target ID (or explicit unresolved state) is restored from the sidecar. Rebuilt dependency edges use `(targetSheetId,row,col)` for each valid in-bounds reference with a present target sheet. Deleted or unresolved targets produce broken-reference results and no edge.
- **Rename and duplicate names:** rename validation rejects case-insensitive collision before commit. Manifest validation independently enforces the same uniqueness rule. IDs, not names, disambiguate all existing bound formulas.

Formula digest is SHA-256 over exact stored formula text encoded as UTF-8; encode the digest as lowercase hexadecimal. If source-text normalization is ever introduced, it requires a manifest version bump and migration; binding occurrence identity must not depend on locale-specific rendering.

## 6. Restore state machine: validate before exposure

A whole-workbook restore is a staged transaction. No sheet, event, pivot, or scheduler state from the candidate becomes visible until all required stages succeed.

1. **Read frame:** validate magic, envelope version, flags, total length, metadata length, sheet count, CRC, directory bounds, and exact payload partitioning. Enforce configured maximum sizes before allocation.
2. **Migrate envelope:** apply registered stepwise manifest upgraders to a new immutable candidate object. Reject unknown versions or missing migration steps.
3. **Validate manifest invariants:** check IDs, high-water mark, names, order, active ID, binding-row uniqueness, formula digest syntax, and allowed missing target IDs.
4. **Decode payloads:** for each sheet, verify declared length and payload checksum; call `SnapshotCodec.decode` on a bounded byte view; verify decoded CSEX version path; do not pass unbounded or malformed slices to a live sheet.
5. **Validate worksheet snapshots:** validate all cell, merge, dimension, visibility, style, drawing, DAG, and volatile coordinates/structures. Existing `applySnapshot` validates some coordinates before clearing its stores, but its in-place application is not the workbook-wide atomicity boundary; stage each sheet on a fresh temporary object.
6. **Construct staging owner:** allocate fresh worksheet stores/objects and a fresh workbook identity directory. Install every sheet in manifest order with its persisted ID/name; set active ID only after validation. Do not share references with an existing owner.
7. **Rebind formulas:** parse all formulas after all sheet IDs/names exist, validate every sidecar `(owner,address,digest,occurrence,targetId-or-unresolved)`, then construct typed bound references. Keep missing targets explicitly unresolved; never resolve them by display name.
8. **Rebuild derived state:** rebuild local dependency graphs, qualified dependency edges/range watchers, volatile registrations, pivot indexes, event subscriptions, and scheduler state from authoritative serialized inputs. Do not trust serialized adjacency or runtime subscriptions. Restore cached cell values as provisional only; D4.5 recomputes dirty formulas in topological order and marks the generation clean only after commits complete.
9. **Publish atomically:** after all prior stages succeed, swap the fully staged owner into the public reference and publish one restore-complete event. On any error, discard staging and leave the prior live workbook, active sheet, subscriptions, and caches untouched.

**Recovery/cache rule:** persisted formula results are cache hints for display and migration compatibility, not proof of current correctness. The restore path marks formula nodes dirty unless the future D4.5 generation/checkpoint contract can prove cache validity. It must not expose a partially recalculated workbook as settled. The manifest itself does not specify calculation ordering; D4.5 does.

## 7. Acceptance matrix for implementation

The following are required future verification scenarios, not tests run in D4.4.

| Case | Expected result |
| --- | --- |
| Manifest v1 with CSEX v1 payloads | Decodes, upgrades worksheet object through registered upgrader, preserves IDs/order, restores atomically. |
| Manifest v1 with CSEX v2 payloads | CRC and lengths validate; object and binary version axes remain independent. |
| Missing/unknown manifest or payload upgrader | Reject before mutation; exact diagnostic identifies version and sheet when applicable. |
| Truncated header, metadata, directory, or payload | Reject without changing prior workbook or publishing events. |
| CRC mismatch / overlapping section or payload bounds | Reject before staging becomes observable. |
| Duplicate IDs/names, invalid name/order/active ID, sequence collision | Reject whole candidate; no repair-by-renumbering. |
| Valid formula-binding sidecar | Exact formula digest and token ordinal match; target ID survives rename and round-trip. |
| Deleted target followed by same-name new sheet | Old reference remains `#REF!`; new same-name sheet does not capture it. A newly entered formula can bind to the new ID. A qualifier unresolved when first bound also remains `#REF!` after a same-name sheet is created. |
| Rename then save/reload | Formula source spelling retained; binding still points to original target ID; directory uses new name. |
| Snapshot restore with forward/cross-sheet refs in reversed manifest order | All bindings resolve identically because all sheets are installed before second-pass binding. |

| Legacy loose snapshot import | Fresh workbook/sheet IDs allocated; provenance recorded; unavailable identity is not inferred. |

| Dirty formulas after restore | D4.5 recomputes before generation is marked clean; binder never recursively recalculates a stale cache. |

## 8. Risks, non-goals, and dependencies

- **CS-002D4.3 remains blocked on CS-001C.** This design does not authorize transaction implementation or bypass its mutation/rollback contract.
- **CS-002D4.5 is required** for generation-valid caches, workbook-wide dependency rebuild, and pre-publication recomputation policy. This document does not implement a scheduler.
- **CSEX decoder hardening is a prerequisite** for treating untrusted payload bytes as safe. Present code reads section lengths but does not validate them, and currently ignores unknown sections; the future decoder must validate frame bounds, required sections, duplicate sections, flags, and trailing bytes.
- **Feature coverage remains explicitly bounded.** Until omitted worksheet/workbook features have a versioned serialization contract, do not advertise full-fidelity native persistence.
- **Out of scope:** production code, migration execution, codecs, tests, UI save flows, XLSX format, cloud storage, security review, and baseline reruns. The historical 105-failure inventory remains reference-only.

**Next:** review this design. No production changes, build/test runs, or baseline reset were authorized or performed in CS-002D4.4.
