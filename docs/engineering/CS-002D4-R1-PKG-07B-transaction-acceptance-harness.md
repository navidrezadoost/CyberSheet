# CS-002D4-R1 PKG-07B — Transaction acceptance harness specification

**Status:** Ready to activate after contract approval and implementation authorization. No tests were added or executed in this lane.
**Scope:** Candidate single-comment Workbook-owned deletion using the PKG-06 Policy C before-image (retain the original comments-array reference on the first effective replacement). This is a future acceptance specification, not evidence that a Workbook delete API or Journal/Snapshot integration exists.
**Production mutation boundary:** The existing seven Workbook mutation operations remain unchanged. This document does not authorize an eighth operation.
**Overall CS-002D4-R1 acceptance:** WITHHELD.

## Activation gates

Do not turn this specification into executable tests until all of the following are true:

1. The authorized Worksheet/API and Workbook/API owners have approved the operation contract, including signature, target scope, cascade, duplicate-ID behavior, missing-state/no-op result, repeated-operation semantics, and event contract.
2. A separate implementation authorization names the approved operation and production strategy boundary.
3. The implementation exposes an actual supported path for exercising both Journal and Snapshot. Do not add test-only production hooks or infer Snapshot coverage by reusing Journal restoration.
4. The test can construct fixtures through supported APIs. Do not cast around absent APIs, reach into private state, or intentionally write tests that fail TypeScript compilation because the candidate surface does not yet exist.

Until activation, all contract-dependent rows below are proposals awaiting owner approval. This spec does not amend authoritative contract text or promote any disposition.

## Harness structure after activation

Use the real Workbook mutation entry point and transaction context supplied by the approved public API. Run the comment-delete cases independently under the production Journal strategy and the explicitly selected Snapshot strategy. Keep standalone `Worksheet.deleteComment` tests separate: they verify the existing standalone behavior, not Workbook transaction integration.

For identity-sensitive cases, retain test references before mutation to the target cell, comments array, each comment node, and selected nested graph nodes. Compare references with identity assertions in addition to structural values. Capture cell presence and unrelated cell fields before the transaction. Observe both the Worksheet event surface and Workbook event surface separately; assert within-surface contract only, never a global callback completion order between surfaces unless the owner explicitly approves one.

Each fault case should use an already-supported, narrowly scoped test seam at a documented transaction phase. If the implementation offers no supported seam, record that cut as untested; do not add a production hook solely to satisfy this matrix. Ensure cleanup of injected hooks in `finally`/test teardown.

## Required transaction invariants to verify directly

- **Before-image:** capture cell-presence state and the original comments-array reference before the first effective replacement for a cell; do not overwrite it on later deletes in the same transaction.
- **Replacement-only window:** the candidate operation must not mutate the retained array or any node reachable from it between capture and rollback/commit. A retained external alias that mutates in place is outside what reference restoration can rewind; document and test that limitation without claiming arbitrary graph rollback.
- **Rollback:** restore absence versus presence correctly, and restore an existing cell's original comments reference without traversing or cloning metadata. Preserve unrelated cell fields and suppress buffered comment notifications.
- **Commit:** publish only after successful commit, with operation frequency and payload fixed by the approved contract. Observer exceptions follow the established event-surface isolation policy and do not undo committed state.
- **Strategy parity:** Journal and Snapshot each demonstrate the invariants using their own implementation path. A passing standalone Worksheet test or PKG-06 fault model cannot substitute.

## Evidence classification and non-claims

PKG-05/06 provide useful preparation: source inspection of replacement-only standalone deletion, a test-local exact-reference graph model, and test-local failure-cut/recovery classification. PKG-06 also exercised existing seven-operation Journal/Snapshot behavior and prior comment reads. These are **simulation and adjacent-operation evidence**. They did not execute Workbook comment deletion because no such Workbook operation was present, and they did not establish comment-delete event buffering, rollback, failure health, or Journal/Snapshot parity in production.

This document defines future acceptance coverage only. It does not assert that any API, return type, no-op rule, cascade rule, event payload, cross-sheet capability, or recovery behavior has been approved. It does not authorize source or test changes, owner reads for arbitrary metadata graphs, a general metadata normalizer, Application forwarding, or expansion of the seven-operation boundary. Overall CS-002D4-R1 acceptance remains **WITHHELD**.
