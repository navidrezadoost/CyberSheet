## 1. Goal and scheduling decisions

Specify the workbook-level dependency and recalculation contract required for typed, value-only cross-sheet binding. The scheduler reads committed precedent caches; therefore, a formula may run only after every dirty precedent in its current calculation generation has committed.

**Normative design decisions:**

1. One workbook calculation pass owns one unified dependency view keyed by `(WorksheetId, packedCellKey)`. The workbook owns only qualified cross-sheet dependency records; each `Worksheet` remains the sole owner of its local point edges and local range watchers. A non-owning composite view supplies global traversal, deterministic order, and SCC analysis. No edge is registered in two authoritative stores.
2. Graph direction is precedent → dependent. A dependency record is the inverse read relation: formula cell → precedents. Local formula references/ranges remain in the worksheet `DependencyGraph`; qualified references whose target sheet differs from the formula's owner are stored in the workbook dependency index. Explicitly qualified same-sheet references are local edges after binding.
3. The workbook computes a complete dirty closure, classifies SCCs once, and schedules a stable topological order. Tie-breaking is `(WorksheetId, packedCellKey)` using an ordinal comparison of the opaque persisted ID followed by numeric packed key. Worksheet IDs are not parsed for ordering.
4. Priority and time slicing may select among currently ready nodes but must never make a dependent run before a dirty precedent. A simple FIFO topological execution is the correctness baseline. The existing priority-heap behavior is not sufficient as the global dependency authority.
5. One workbook-owned calculation generation invalidates stale worker results and marks caches current only after their dirty predecessors are current and the whole pass commits. The binder never repairs stale caches by recursive evaluation.
6. One workbook-owned SCC analysis is the only cycle authority for workbook-owned formulas. Standalone `Worksheet.recalc()` / `autoRecalculate()` retain their current worksheet-local authority when no workbook scheduler is attached.
7. Mutation atomicity remains owned by CS-001C/D4.3. Restore atomicity remains owned by the D4.4 staged restore boundary. D4.5 does not implement a parallel transaction or restore mechanism.

### Current correctness gaps relevant to design

- Local `DependencyGraph.getEvalOrder()` queue seeding and successor iteration derive from insertion order, not a specified stable key order. This is topologically valid but does not define cross-run canonical ordering.
- Kahn's residual set contains cycle members **and** nodes blocked downstream of a cycle; `findCycles()` returns actual SCCs. The scheduler must retain that distinction in diagnostics and status.
- `RecomputeScheduler` orders first by priority, then by `topoOrder`. For an arbitrary mixed-priority dirty subgraph, this can run a dependent in a higher-priority lane before a precedent in a lower-priority lane. D4.5 makes dependency readiness dominant.
- Scheduler generation currently invalidates queued single-sheet tasks, but `Worksheet.applyFormulaResults()` has no generation/revision validation and can clear current dirty state from an old result batch if called with stale addresses.
- Worker protocol IDs correlate RPC calls only. Current worker recalc supplies no evaluator and does not return cell values.
- `SpreadsheetEngine.run()` prevents same-engine mutation while computing, but it commits the mutation transaction before formula computation. Cross-sheet atomic commit/rollback semantics and failure recovery require CS-001C/D4.3; do not infer them from the single-sheet flow.

## 3. Unified dependency relation without duplicate edge ownership

### Identity and node model

A workbook formula node is `NodeId = (WorksheetId, NodeKey)`, where `NodeKey` is the existing packed row/column key for a valid one-based worksheet coordinate. A sheet ID is always interpreted through the owning workbook directory; equal row/column pairs on different IDs are different nodes. Invalid/out-of-bounds coordinates are rejected as `#REF!` at parse/bind time and never enter any graph/index.

Each formula has exactly one authoritative dependency owner:

| Dependency | Authoritative owner | Workbook view |
| --- | --- | --- |
| Unqualified local point | Formula owner's `DependencyGraph` | Enumerated/projected into global node relation during workbook plan construction. |
| Unqualified local range | Formula owner's `DependencyGraph` range watcher | Queried by the local graph; matching formula-node successors are projected into global dirty traversal. |
| Explicit qualifier resolving to formula owner's own ID | Formula owner's `DependencyGraph` | Treated as local after typed binding. |
| Qualified point to a different sheet ID | Workbook qualified-dependency index, keyed by target `WorksheetId + NodeKey`, pointing to dependent `(ownerId, formulaKey)`. | Projected into global precedent/dependent relation. |
| Qualified range to a different sheet ID | Workbook qualified-range watcher keyed by target sheet ID and inclusive rectangle, with dependent workbook node. | Matching changed cells/range mutations yield global dependents; graph view exposes formula-to-precedent relation for topological/SCC analysis. |

A composite workbook relation is a read-only graph view over these stores. It may materialize an ephemeral adjacency set for one pass, but it does not write local edges into the workbook index or workbook edges into sheet graphs. Formula replacement removes old local and qualified registrations from their original owners before installing new registrations; old and new dependent closures are both dirtied.

### Range semantics

Ranges are inclusive one-based rectangles, normalized to ordered endpoints after bounds validation. Local range watchers remain in `DependencyGraph`; qualified range watchers are indexed by target `WorksheetId`. A change at `(targetSheetId,row,col)` invalidates every qualified formula whose rectangle contains the coordinate, then propagates through the unified dependent closure. Empty in-bounds cells are valid precedents. Invalid endpoints produce `#REF!` and no edge.

Correctness-first implementation may test each range watcher against each changed cell by a linear scan. The required result is exact invalidation, with deterministic de-duplication. An interval tree, row/column buckets, R-tree, segment tree, or other indexed rectangle query is a separate optimization that must preserve the same semantics and prove its maintenance invariants.

## 4. Dirty propagation and structural changes

Dirty marking is workbook-scoped and idempotent within a generation. The pass seeds changed data/formula nodes, expands local graph successors and local range hits, crosses qualified edges/range watchers, then continues through all downstream sheets until closure. The final plan includes only formula nodes to evaluate; changed literal cells are precedents but not formula tasks.

| Trigger | Required graph/cache action |
| --- | --- |
| Literal/value edit | After mutation commit, seed that cell and propagate through local and qualified dependents/ranges transitively. |
| Formula insertion or replacement | Remove old edges/watchers; parse/bind new references; install one authoritative owner per relation; dirty the formula node plus downstream closure through both old and new graph relationships. |
| Formula clear / formula-to-literal replacement | Remove formula node's outgoing read edges and volatility registration; dirty its consumers so they read the new literal/blank cache. |
| Qualified sheet rename | Preserve target ID and dependency ownership. No value-dependent graph edge changes. Dirty formulas whose semantics inspect display names/formula text only if that function's result is name-sensitive; do not rebind by old spelling. |
| Sheet deletion | Remove its owned nodes and local graph; remove its outgoing qualified dependencies; retain dependents' binding target IDs as unresolved per D4.4, dirty those dependents and propagate `#REF!` downstream. |
| Same-name sheet recreation | Allocate a new ID; old bindings remain unresolved and `#REF!`; do not attach edges to the replacement. New formulas resolve the current name. |
| Volatile refresh | Seed every volatile formula in the selected calculation scope, then propagate to all local/cross-sheet dependents. Volatile formula registration changes with formula replacement and restore. |
| Snapshot restore | Validate/stage per D4.4, rebuild all sheet and qualified registrations from formula text + binding sidecar, mark formulas dirty for a fresh generation, then evaluate before claiming caches current. |

Renaming a worksheet does not change its ID. The binding sidecar preserves existing formula targets despite source spelling. A formula edit is a new bind operation against the current name directory. `FORMULATEXT` and other metadata functions remain governed by D4.2 and require inspection of the bound reference operand.

## 5. Deterministic calculation and cycle authority

### Pass contract

For a calculation generation `G`, the workbook scheduler performs these phases:

1. Freeze the committed mutation/rebuild input set for `G`; capture formula revisions and source versions for dirty formulas and their referenced cells.
2. Compute the global dirty closure across local graphs and workbook-owned qualified indexes. Include volatile formulas selected for this pass.
3. Build the composite dirty formula graph and compute deterministic SCCs over all selected nodes, including self-edges. Sort nodes and each SCC by `(WorksheetId, packedCellKey)`; sort SCC list lexicographically by its first node.
4. Remove true cycle SCC members and their blocked descendants from ordinary ready execution. Topologically order the remaining acyclic nodes with a stable ready queue. Choose only among currently zero-in-degree nodes using the canonical node key; UI priority may adjust order only inside the ready set.
5. Evaluate a ready formula exactly once in `G`. The binder reads only current committed caches. Commit the result for that same node before releasing dependent nodes. If result is an error/array/entity, preserve the existing `FormulaValue` contract.
6. Assign cycle results: every true SCC member receives `#CIRC!` when iteration is disabled. Acyclic descendants blocked by the SCC receive propagated `#CIRC!` as their evaluated result/status, but diagnostics label them **blocked descendants**, not cycle members. Independent branches still evaluate.
7. Once all scheduled results and cycle/blocked outcomes are committed and accepted, mark the participating caches current for `G`, clear only this generation's dirty state, then publish buffered events in deterministic node order. If `G` is invalidated or fails, do not mark it current or publish a successful completion event.

### Cycle semantics

There is one SCC authority per active workbook pass. It operates over the composite relation; individual worksheet SCC results are not combined after the fact. A true SCC is either size > 1 or size 1 with a self-edge. A blocked descendant is reachable from a cycle SCC but is not a member of any cyclic SCC. Under the accepted iteration-disabled policy from CS-002B, cycle members commit `#CIRC!`; dependent formulas propagate that error. Cycles in unrelated components do not block or poison independent acyclic formulas.

Standalone worksheets continue to use `DependencyGraph`/`RecalcCoordinator` cycle authority, including local SCC diagnostics and error commitment. A workbook-owned sheet cannot concurrently run standalone recalc for the same calculation state; the owner mode is explicit and exclusive.

## 6. Cache generations, worker results, and event publication

### Cache freshness

The workbook owns a monotonically increasing `calculationGeneration`. Every committed mutation set, restore, structural dependency change, or explicit volatile refresh that invalidates formula results starts a new generation. Each formula cache has a validity stamp or equivalent dependency revision token. A formula cache is current for `G` only after:

- its formula text/revision and bound reference identities match the captured inputs;
- every dirty precedent needed by the formula has committed in `G` (or a clean precedent's cache is valid against its current input revision);
- the result is committed to the same `(WorksheetId, packedCellKey)`; and
- the pass has not been superseded by a newer generation.

A cache read of a stale formula result is not silently accepted as current. The scheduler must order/re-evaluate its dirty precedent first; if the predecessor is not included because dependency registration is corrupt or stale, fail the pass as an invariant violation rather than recursively evaluating the precedent inside the binder.

### Worker/task result acceptance

Every asynchronous evaluation result must carry at least:

```ts
interface CalculationResultEnvelope {
  workbookId: string;
  calculationGeneration: number;
  sheetId: WorksheetId;
  packedCellKey: number;
  formulaRevision: number;       // or digest of exact formula text + binding revision
  taskId: string;                // unique within generation
  value: FormulaValue;
}
```

Accept a result only if workbook ID, generation, sheet ID, cell formula/revision, binding revision, and pending task identity all match current state. Otherwise discard it without writing a cache, clearing dirty state, or emitting a formula-result event. Request/response ID only correlates a worker RPC and is not freshness authority. The worker host serializes mutations per worker; if evaluation is distributed across workers, deterministic topological readiness and result acceptance remain workbook-owner responsibilities.

### Events

User-authored mutation events and derived formula-result events remain distinct (`origin: 'formula-result'` per the additive CS-002A contract). During a workbook calculation, buffer per-cell derived events and aggregate `formulasEvaluated`/cycle diagnostics. Publish only after a successful generation commit, in canonical `(WorksheetId, packedCellKey)` order; publish one pass-completion event after cell events and after dirty/cache state is stable. Do not put derived formula writes into the user mutation patch/journal.

If a pass is invalidated, superseded, or fails before commit, discard its buffered success events. Transaction rollback/no-transient-publication semantics are delegated to CS-001C/D4.3. One-sheet `SpreadsheetEngine` event behavior remains unchanged by this design stage.

## 7. Transaction and restoration boundaries

- **CS-001C / D4.3 transaction blocker:** transaction commit defines the mutation set the scheduler sees. D4.5 must consume a committed workbook-wide input revision and may not invent its own mutation journal, nested transaction policy, rollback snapshot, or cross-sheet event aggregation. The transaction contract must specify whether recalculation failure can abort/rollback mutation commit and how old cache validity is restored.
- **D4.4 restore contract:** only a fully decoded, validated, staged workbook can enter the scheduler. Restore rebuilds indexes/graphs from persisted formula text and binding IDs, marks formulas stale/dirty, and does not expose an apparently settled workbook until the initial calculation generation completes under the restore publication policy.
- **No mixed ownership:** do not let worksheet-local `autoRecalculate`, a `SpreadsheetEngine` scheduler, a worker recalc call, and the workbook scheduler concurrently clear or commit the same dirty formulas. The workbook owner is the single coordinator for adopted sheets; standalone entry points remain valid only outside workbook-owned scheduling.

## 8. Minimal correctness architecture vs optimizations

| Minimal correctness architecture (required first) | Later performance-certified optimization (not a correctness dependency) |
| --- | --- |
| Workbook identity-keyed node records and workbook-owned qualified point/range indexes. | Compressed adjacency storage, incremental global graph projection, or compact multilevel indexes. |
| Exact dirty closure across local graph successors and qualified edges/range scans. | Indexed rectangle queries (interval trees, row buckets, R-trees) after workloads establish material cost. |
| Full deterministic SCC analysis of the selected workbook graph; distinguish members from blocked descendants. | Incremental SCC maintenance or localized cycle recomputation. |
| Stable topological ready queue with cache commit before releasing dependents. | Parallel evaluation of independent ready nodes; must preserve deterministic commits/events and cache visibility. |
| Per-generation stale-result rejection using identity, formula/binding revision, and task token. | Worker pools, speculative work, cancellation optimizations, or persistent task caches. |
| Buffer result events and publish after generation completion. | Event coalescing, chunked UI notifications, and adaptive time slicing. |
| Mark all affected caches dirty on restore; recompute before declaring generation current. | Persisted valid-cache checkpoints with input-generation proofs. |

Performance work must report data size, formula count, graph density, range count/area, mutation shape, hardware/runtime, memory, evaluation count, and runtime distribution. It cannot replace correctness gates or hide unstable baselines.

## 9. Acceptance matrix for future implementation

These are required implementation results, not tests run for this design-only ticket.

| Scenario | Expected result |
| --- | --- |
| Stable ordering | Repeated runs over the same graph/inputs produce identical order by `(WorksheetId, packedCellKey)`; dependents never precede dirty precedents. |
| Mixed-priority ready queue | A high-visibility dependent waits until its lower-priority precedent commits; priority only selects among ready nodes. |
| Local-to-cross-sheet chain | Edit `SheetA!A1` → `SheetB!B1='SheetA'!A1*2` → `SheetA!C1=B1+5`; all recompute transitively, with each precedent committed before dependent binder reads. |
| Cross-sheet qualified range | An interior edit to a qualified range dirties its formula once and propagates to transitive dependents on other sheets. |
| Mixed-tier cycle | A local edge plus qualified edge forming an SCC is found by one global authority; every SCC member is classified as a cycle member and commits `#CIRC!`. |
| Cycle blocked descendant | A formula downstream of a cycle is diagnosed as blocked descendant, not SCC member; its value propagates `#CIRC!`; an independent branch still calculates. |
| Recovery after cycle removal | Removing one cycle edge invalidates the generation, clears obsolete cycle status, and recomputes former members/descendants to current values. |
| Self-cycle and self-inclusive range | Self-edge is an SCC; cycle semantics follow the disabled-iteration policy and do not depend on traversal order. |
| Formula replacement | Replacing a qualified ref with local/literal removes old cross-sheet edge, adds only the new owner edge, and dirties consumers of old/new results. |
| Rename | Existing reference remains attached to same target ID; graph edges do not move; metadata-sensitive formulas update if needed. |
| Delete and same-name recreation | Dependents of deleted target get `#REF!`; new same-name sheet does not capture old edges or bindings. |
| Out-of-bounds reference | Resolves to `#REF!`, has no graph node/edge, and does not collide in packed identity. |
| Volatile cross-sheet dependent | Explicit volatile refresh dirties volatile formula and all transitive cross-sheet dependents once. |
| Stale cache guard | A dependent is not evaluated against an old dirty precedent cache. Missing dependency registration fails invariant checks rather than triggering recursive binder evaluation. |
| Concurrent worker completion | Newer generation or changed formula/binding revision causes old result to be discarded; it cannot overwrite cache, clear dirty state, or emit events. |
| Event commit | Derived events appear only after successful pass commit, ordered deterministically; invalidated/failed pass emits no success batch. |
| Snapshot restoration | D4.4 IDs and formula bindings rebuild the composite graph; caches become current only after the initial recompute generation commits. |
| Independent workbooks | Equal sheet names/coordinates in separate workbooks do not share IDs, edges, caches, workers, events, or dirty state. |
| Standalone worksheet mode | Direct local `Worksheet.recalc()`/`autoRecalculate()` retain local graph behavior and are excluded from workbook scheduling authority. |
| Worker currently no evaluator | Worker test/diagnostic records that current no-op `ws.recalc(() => {})` is not calculation correctness evidence; future worker path commits real `FormulaValue`s only through generation checks. |
