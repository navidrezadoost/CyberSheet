**Scope:** D2-11 mutation families beyond the existing seven Workbook transaction operations.
**Method:** Reconcile the PKG-03B coverage map and source-owner evidence; assess each family separately for Journal restoration, Snapshot comparison, event and persistence boundaries, API authority, test prerequisites, and integration risk.

**Authorization:** Documentation/analysis only. No implementation, test, contract, ledger, or frozen-register changes.

## Dependency closure and critical risks

| Dependency | Blocks / constrains | Evidence needed to close | Risk if skipped |
| --- | --- | --- | --- |
| Comment exact-state semantics and testability | One-comment delete implementation | PKG-04A detached CellRecord/comment before-image; PKG-04B non-breaking fixtures and explicit future acceptance cases; Journal/Snapshot fault parity | Shallow Journal restore can pass simple deletion but fail if nested values or in-place edits occur. |
| API authority and implementation authorization | Every new Workbook operation | PKG-04C traceable owner decision for signature, no-op/cascade/event semantics and explicit authorization | Engineering proposal could be mistaken for a public contract or permission to add an eighth operation. |
| D5-01 disposition | Any new observable event operation | Owner decision or explicit preservation of existing event behavior with no global cross-layer ordering assertion | A new event surface could assert unsupported cross-layer sequencing. |
| D5-05 Application authority/schema | Application-level forwarding only | Named authority, stable event names/payloads and migration policy | Accidental public schema and ownership expansion. Keep all candidates at current Worksheet/Workbook surfaces unless approved. |
| State-owner inventory | Visibility, CF, volatile, drawings, Pivot and structural operations | Each owner and all derived/observer state identified with exact before-image | Restoring primary state while leaving stale caches, graph edges, accumulators, or resources. |
| Persistence contract | Any durable file/checkpoint promise | Host safe-replace and crash semantics plus format fixtures | In-memory rollback may be incorrectly claimed to restore an externally changed file. |
| History contract | Undo/redo | Separate replay, retention, branch and failure policy | History can diverge from committed state or make rollback non-atomic. |
| Structural/reference semantics | Row/column/sheet insert/delete | D1/D6 identity and formula-reference policy; dependent-store mapping | A cell/dimension restore can leave broken references or rebind deleted IDs. |
| Pivot D3 integration | Pivot participation in source mutation | Stale-result policy, owner-backed reachability and full source/refresh fault model | Last-good snapshot may be paired with invalid incremental state or misleading freshness. |
| Drawing/resource lifecycle | Drawing transactions | Resource acquisition/disposal ownership and renderer failure behavior | State rollback may leak loaded images/listeners or dispose a live resource. |

## Risk-ranked disposition

1. **First bounded candidate:** one-comment deletion, only after PKG-04R confirms the combined contract, test, and authority prerequisites. This recommendation preserves the current `deleteReplies=true` behavior as a candidate default and adds no Application event; it does not pre-approve either choice.
2. **Next independent store candidate:** one visibility transition, after typed Workbook event authority and exact membership/no-op behavior are settled.
3. **Separate bounded families:** comment add, comment update, and one CF operation, each with a distinct nested-state before-image and event/evaluation test matrix.
4. **Require further architectural closure first:** volatile scheduling, drawings, structural changes, Pivot integration, persistence, and Workbook history. These have cross-owner or asynchronous/durable effects and should not be bundled merely to reduce package count.

This register is a planning artifact, not a global D2-11 closure. It makes no D5 approval claim and authorizes no source/test change. The seven current transaction operations remain the only production transaction operations. Overall CS-002D4-R1 acceptance remains **WITHHELD**.
