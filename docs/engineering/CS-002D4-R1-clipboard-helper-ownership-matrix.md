## Contract choices for a later decision

1. **Owner reads:** Decide whether operations accepting `Worksheet | WorkbookSheetView` should require owner-backed views for owned data, or fail closed when a raw Worksheet has been adopted. A public `workbookId` property check is not an authoritative ownership test.
2. **Standalone compatibility:** Preserve direct standalone Worksheet clipboard behavior unless a separately approved API contract changes it.
3. **Unavailable owner Cut/Paste:** Decide how the UI reports operations that currently reject an owner view, including rejected async Paste promises. The current helper tests do not establish production browser error presentation.
4. **Snapshot diagnostics:** Decide whether PasteCommand and ClipboardService diagnostics may contain cached cell values. Detaching a cell snapshot prevents reference aliasing but does not mask primitive cached values.
5. **Reachability:** Keep internal adoption-seam findings separate from supported Workbook, ExcelApp, Ribbon, and public package ingress. The synchronous helper has no found production caller and is absent from the React root barrel; direct deep-module imports remain a separate consumer question.

## Scope and verification

This is a source/evidence consolidation only. No production code, test, implementation disposition, or frozen register was changed for this matrix. It does not close the external async Paste branch, retained-raw Copy source candidate, standalone Paste completion, direct-source `ExcelRibbon`, browser rejection reporting, or the broader R1 inventory.
