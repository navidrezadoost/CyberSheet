## Contracts

> Services retaining a raw Worksheet are standalone-only unless their owner-transition behavior is explicitly verified. Workbook-owned first-party consumers must use authorized owner-backed views for formula-sensitive observations. A retained raw handle's mutation guards do not, by themselves, establish formula-read confidentiality.

This is a provisional review contract, not a claim that all listed services comply. Current evidence confirms the FindService owner-view path is safe for the reviewed formula-sensitive observations and separately demonstrates cached-value exposure if a raw Worksheet is internally adopted after FindService construction. DataManager's three tested entry points terminate on zero-based reads for the exercised standalone configurations. EditingManager and ExportPlugin have focused internal retained-raw read-disclosure characterizations, but no supported first-party constructor callers were found. AccessibilityManager remains blocked by its current constructor failure. None of these module-level findings closes individual frozen semantic records.

## DataManager row-zero characterization — 2026-10-20

A focused standalone-Worksheet regression exercises `sort`, `filter`, and `group` independently. All three reach `Worksheet.getCell()` with row `0` and throw the one-based-address `RangeError` before completing their first comparison, predicate, or group key. `sort` successfully reads `{ row: 1, col: 1 }`, then its next read `{ row: 0, col: 1 }` throws; its caller comparator is not invoked. `filter` requests `{ row: 0, col: 2 }` and does not invoke its predicate. `group` requests `{ row: 0, col: 2 }` and throws before forming its first group key.

Because none of the three tested paths completes against a real standalone Worksheet, this checkpoint did not exercise the internal raw-Worksheet adoption lifecycle. It establishes the current reachability boundary for these configurations without normalizing coordinates or establishing their behavior for external Worksheet implementations. The standalone coordinate incompatibility is confirmed; formula-cache disclosure through these DataManager operations remains unconfirmed. No production change or disposition promotion follows. The focused Jest selection passes 3/3 with default diagnostics; the renderer-canvas package typecheck and `git diff --check` pass. R1 acceptance remains withheld.

## EditingManager clipboard characterization — 2026-10-20

The focused clipboard regression confirms ordinary standalone copy with a valid one-based selection. Plain text, HTML, and CSV contain the cell value; the custom `application/x-cyber-sheet` JSON also serializes the copied cell's formula and comment fields. A manager constructed with the standalone Worksheet retains that raw reference. After the internal adoption helper adopts the sheet, copy still publishes the formula cached value (`42`) through all four formats. This reproduces a cached-value read disclosure for the internal retained-raw lifecycle; it does not demonstrate a supported first-party Workbook route.

The test dispatches a document `cut` event after adoption and captures the actual registered callback failures through `window` `error` events. `document.dispatchEvent()` does not throw those callback exceptions to its caller; it returns `false` because the handler prevents the cut event's default action, while jsdom reports two owner-guard errors through the uncaught-error event mechanism. This demonstrates that both concurrently registered manager listeners run: each publishes all four clipboard formats before its `setCellValue()` call rejects. The worksheet's cached value, formula, and comment remain unchanged. The test's custom JSON clipboard payload records `isCut: false`, because copy serializes it before `handleCut()` sets its manager-local flag. This is the observed ordering for this path, not a generalized completed-cut contract or an R4 event-ordering claim.

The constructor registers document listeners and exposes no disposal API. Two EditingManager instances remain subscribed and both handle later copy/cut events. This is a listener-lifetime compatibility finding separate from Workbook read authority. The demonstrated cached-value publication still requires the internal raw-Worksheet adoption transition; no supported first-party caller or public adoption route was found. The clipboard characterization subtask is evidence-complete for the tested paths; the 21 semantic dispositions remain open. No production behavior or ledger disposition changed. Focused Jest passes 1/1 with default diagnostics; renderer-canvas package typecheck passes (the package config excludes tests). R1 acceptance remains withheld.

## ExportPlugin serialized-output characterization — 2026-10-20

The focused regression constructs ExportPlugin with a standalone Worksheet and an explicit valid range, then adopts the retained Worksheet through the internal helper. CSV returns `42` and JSON returns `[{"col1":42}]` both before and after adoption, exposing the formula cached value through serialized results. The JSON row contains the value only; formula and comment data are not included by this export path. This CSV/JSON characterization is evidence-complete for the tested explicit range. By contrast, an export without `options.range` calls `getEffectiveRange()`, whose used-range scan begins at `(0,0)`; a real Worksheet rejects that address before CSV export. This confirms an executable internal retained-raw disclosure on explicit-range CSV/JSON paths and a separate coordinate defect on the default-range path.

No Workbook mutation is attempted and no public raw-sheet adoption route or first-party ExportPlugin constructor caller was found. Static `copyToClipboard()` and `download()` can publish the returned serialized outputs; those publication APIs were not separately exercised. Other explicit ranges and external Worksheet implementations remain open. The eight ExportPlugin semantic dispositions remain `open-not-reconciled`; no production change or promotion follows. Focused CSV/JSON Jest passes 1/1 with default diagnostics. R1 acceptance remains withheld.

### ExportPlugin PNG draw-input follow-up — 2026-10-20

A focused test supplies only a stub `OffscreenCanvas`, 2D drawing context, and `convertToBlob()` implementation. With a valid explicit range and a retained Worksheet adopted through the internal helper, the `fillText()` draw call receives cached formula value `42`. The fake `convertToBlob()` returns a placeholder Blob and does not rasterize text or encode a PNG dependent on that value. Thus the adopted formula result reaches the canvas text-rendering API, but this test does not demonstrate that actual PNG pixels or encoded bytes disclose it. The claim of PNG output disclosure remains open pending a real pixel/encoding dependency check.

With no explicit range, PNG rejects at `(0,0)` during used-range discovery before constructing OffscreenCanvas; the test verifies the constructor is not called on this path. This establishes the default-range coordinate failure separately from explicit-range read behavior. The test passes 2/2 across the ExportPlugin CSV/JSON and PNG cases with default diagnostics.
