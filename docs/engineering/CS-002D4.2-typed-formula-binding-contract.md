# CS-002D4.2 — Typed Formula Binding Contract

**Status:** Design only · **Priority:** P0 architecture dependency  
**Predecessor:** CS-002D4.1 (identity and migration contract; O1 selected)  
**Parent:** [CS-002D.4 production integration design](../architecture/CS-002D4-production-integration-design.md)  
**Reported:** 2026-10-17  
**Implementation:** Not authorized in this ticket

## 1. Objective and decision

Specify how production formula evaluation represents and resolves local and sheet-qualified cell/range references. This contract replaces the CS-002D.2R prototype's formula-text substitution and `valueOnlyView` proxy with typed references and an optional workbook binding service on the existing `FormulaContext`.

**Decision: retain both parsed-but-unbound and bound reference forms.** Parsing preserves the source qualifier, quoting, absolute markers, and coordinates. A workbook-owned binding step resolves the source qualifier through the D4.1 name-to-`WorksheetId` directory and produces an ID-bound reference for evaluation. The evaluator receives bound references on workbook-owned paths. The source-form reference remains available for formula display, rename handling, reparsing, and snapshot persistence. A bound ID is never reinterpreted as a display name.

The parser must not replace sheet-qualified expressions with literals or rewrite formula text. The workbook binder resolves references to committed values only. It never evaluates a precedent formula. D4.5 owns workbook-wide dependency ordering, cycle handling, and scheduling; D4.2 defines the boundary those systems call.

### Existing recursive precedent evaluation sites

The following production paths recursively evaluate a precedent formula instead of reading its committed cache:

- Ordinary cell and range references: [`evaluateCellReference`](../../packages/core/src/FormulaEngine.ts#L1254) lines 1268–1270, and [`evaluateRangeReference`](../../packages/core/src/FormulaEngine.ts#L1279) lines 1298–1300.
- Entity/member-chain base: [`evaluateChain`](../../packages/core/src/FormulaEngine.ts#L510) lines 520–522.
- Provider pre-resolution for a member chain: `evaluateWithProviders` lines 638–659, especially 653–654.
- Dot member expression: lines 1475–1490, especially 1484–1486.
- Bracket member expression: lines 1556–1571, especially 1565–1567.

D4.2's binder path must not fall through to any of these recursive precedent branches. It must return the committed cell cache (preserving `EntityValue` where member access needs it). The same source `FormulaContext` is also rebuilt in special-function/lambda branches: `LET` around lines 1693–1729 and lambda contexts around lines 1118, 1965, and 2099. Any optional binder and workbook identity must survive each context derivation.

## 3. Typed reference model

The names below are illustrative TypeScript contracts. `WorksheetId` is the opaque branded ID specified by D4.1; it is not a stringly typed display name. `FormulaValue` is the existing exported union, not a new parallel value system.

```ts
type ParsedReference =
  | { kind: 'cell'; qualifier: SheetQualifier | null; cell: ParsedCell }
  | { kind: 'range'; qualifier: SheetQualifier | null; start: ParsedCell; end: ParsedCell };

interface SheetQualifier {
  sourceName: string;       // decoded display name, case preserved
  sourceText: string;       // exact source spelling, including quote/escape form
  wasQuoted: boolean;
}

interface ParsedCell {
  row: number;              // one-based worksheet coordinate
  col: number;              // one-based worksheet coordinate
  absoluteRow: boolean;     // source had $
  absoluteCol: boolean;     // source had $
  inBounds: boolean;        // Excel bounds: rows 1..1,048,576; cols 1..16,384
}

type BoundReference =
  | { kind: 'cell'; sheetId: WorksheetId; row: number; col: number; inBounds: boolean }
  | { kind: 'range'; sheetId: WorksheetId; startRow: number; startCol: number;
      endRow: number; endCol: number; inBounds: boolean };
```

`ParsedReference` is the persisted/reparseable source representation. Binding resolves an explicit qualifier by case-insensitive display-name lookup in the workbook's sheet directory; an unqualified reference binds to the current worksheet's ID. The resulting `BoundReference` contains an ID and one-based coordinates. It does not carry a `Worksheet` object, a display-name lookup key, or a proxy. The retained parsed form supports formula rendering and safe rebinding after rename or restore; bound references are runtime evaluation artifacts and must not become authoritative persisted identity.

Absolute row/column markers do not change the referenced cell's value at evaluation time, but must survive parsing and source-preserving transformations. This ticket does not define copy/fill translation. Quoted sheet names decode doubled apostrophes (for example, `'Owner''s Data'!$A$1`) without losing original spelling. Unquoted and quoted sheet names resolve case-insensitively, consistent with Excel-style sheet-name matching. Coordinates remain one-based at the AST/binder boundary. The parser records out-of-bounds references as invalid; they never form a valid binding.

### Binding lifecycle and identity

- The workbook name directory resolves a parsed qualifier to the current workbook-owned `WorksheetId`.
- A valid bound reference continues to identify that worksheet after a rename; it is not retargeted based on the old display name.
- Deleting the referenced sheet makes the reference unresolved and evaluates it as `#REF!`.
- D4.1 O1 invalidates the construction-time worksheet ID on adoption. A stale ID lookup returns no worksheet and is never silently forwarded to the adopted sheet.
- Whole-workbook restoration recreates the name/ID directory in the restored workbook and rebinds formulas from the saved formula/source form and persisted IDs. Caches, graph state, and subscriptions are rebuilt by the restoration/scheduling workstream, not by the binder.
- Importing a sheet into another workbook allocates a fresh target-workbook ID and remaps references according to D4.1; an ID from the source owner cannot be looked up in the target owner.

## 4. EvaluationContext and binder contract

Add an optional `referenceBinder` to the existing `FormulaContext` in [`formula-types.ts`](../../packages/core/src/types/formula-types.ts#L41); do not create another formula context or value union. For workbook-owned evaluation, construction must ensure a binder is supplied. Standalone callers omit it and retain their present local resolution semantics.

```ts
interface ReferenceBinder {
  resolveCell(ref: BoundReference & { kind: 'cell' }): FormulaValue;
  resolveRange(ref: BoundReference & { kind: 'range' }): FormulaValue;

  // Minimal metadata path for context-aware functions that inspect formulas.
  inspectCell?(ref: BoundReference & { kind: 'cell' }):
    | { exists: false }
    | { exists: true; formula: string | null };
}

interface FormulaContext {
  // existing worksheet/currentCell/lambdaContext/namedLambdas/recursionDepth
  referenceBinder?: ReferenceBinder;
}
```

The binder may be split into parsed-reference binding and bound-reference reads internally, but the evaluator-facing read methods accept only ID-bound references. Resolution returns the existing `FormulaValue` variants:

- Scalars (`number`, `string`, `boolean`, `null`) are returned without string encoding or formula-text substitution.
- A cell whose committed value is an `EntityValue` retains that entity for the existing member-access semantics.
- A cell whose committed value is an `Error` or an existing spreadsheet error token propagates that error as an error value; it must not be quoted or coerced into a string literal.
- Ranges preserve row/column shape using existing 1D/2D `FormulaValue[]` / `FormulaValue[][]` representations as required by the consuming function and current local-range behavior. Empty cells map to `null`.
- Array-valued cells, including dynamic-array anchor caches, are returned as arrays without flattening to scalar or reconstructing a formula string. Spill materialization and collision handling remain the responsibility of the existing spill system.
- A lazy `() => FormulaValue` is returned unchanged. The binder does not invoke it, memoize it, or force a lazy branch that the formula/function would otherwise not evaluate.

`inspectCell` is a metadata-only exception for functions whose contract examines the referenced cell's formula, not its result. It returns only existence and formula text; ordinary reference reads remain value-only. Errors from a bound reference short-circuit operators and function evaluation according to existing formula error propagation; they are not converted into `#NAME?` or `#ERROR!` merely because a qualifier was present.

## 5. Resolution and error semantics

| Condition | Workbook-owned evaluation result | Notes |
| --- | --- | --- |
| Valid local A1 reference | Value from current sheet's committed cache | Local references use the same bound path on workbook-owned sheets. |
| Valid qualified reference; name resolves | Value/cache from the resolved `WorksheetId` and coordinate | Case-insensitive name resolution; no source substitution. |
| Valid syntax; sheet has been deleted or does not exist in this workbook | `Error('#REF!')` | A syntactically valid but unresolved sheet target is a broken reference. |
| Bound ID is stale, invalidated by D4.1 O1, or belongs to another workbook owner | `Error('#REF!')` | Never fall back to a name or current worksheet. |
| Cell/range coordinate is zero, negative, exceeds Excel limits, or range endpoint is invalid | `Error('#REF!')` | No graph binding is created for invalid coordinates. |
| Malformed qualifier/reference syntax or unsupported token shape | `Error('#NAME?')` | Syntax/name recognition failure, not a missing valid target. |
| Empty but in-bounds cell | `null` | Preserve current local blank-cell behavior. |
| Precedent cache contains a spreadsheet error | Propagate that error unchanged | Includes `#CIRC!` committed by the graph and other spreadsheet errors. |
| Formula text is valid but its sheet was deleted after binding | `Error('#REF!')` | Rebinding or stale bound-ID lookup must not silently retarget. |

The CS-002D.2R regression was caused by text substitution that produced formula-like output which the evaluator reparsed as an unknown name, yielding `#NAME?` for a valid qualified reference. The typed binding path must carry a `BoundReference` to the binder and return the referenced `FormulaValue` directly. It must never stringify, splice, and reparse a precedent value. `#NAME?` remains reserved for malformed/unrecognized formula syntax; missing/deleted/stale sheet targets produce `#REF!`, as required by the parent design's error disposition.

## 6. Compatibility and special formula behavior

### Standalone worksheets

When `FormulaContext.referenceBinder` is absent, unqualified local cell/range references continue through the existing worksheet-local logic, including present standalone behavior and local dependency tracking. This ticket does not retrofit a workbook owner or change standalone scheduler semantics. Workbook-qualified references are only guaranteed by the workbook-owned binder path; standalone evaluation retains its current behavior for such syntax rather than inventing a name-resolution environment.

### Formula-inspecting functions

`ISFORMULA` and `FORMULATEXT` are registered as context-aware functions but currently receive evaluated arguments and inspect `context.worksheet`; see [`information-functions.ts`](../../packages/core/src/functions/information/information-functions.ts#L17) and [`exotic-functions.ts`](../../packages/core/src/functions/exotic/exotic-functions.ts#L14). That representation is insufficient for a cross-sheet reference and does not consistently preserve a reference operand. The production parser/evaluator must preserve the typed reference argument through special argument dispatch, then call `inspectCell` on its bound ID/address. `ISFORMULA` tests whether formula text is present. `FORMULATEXT` returns the stored formula or its existing `#N/A` behavior for an absent/non-formula cell. It must not infer formula status from a cached value. `CELL` and any other context-aware function that inspects a cell require the same audit before implementation.

### Arrays, lazy functions, and entities

`FormulaValue` already includes entity values, arrays, errors, and lazy thunks in [`formula-types.ts`](../../packages/core/src/types/formula-types.ts#L16). Binder integration must preserve those values. The evaluator's special-function path (`evaluateFunction`, around lines 1616–1732 and argument parsing at 2304 onward) must retain its existing laziness and range-argument semantics when it starts receiving typed references. It must not eagerly flatten references solely to make them fit a scalar argument path.

Dynamic-array values continue to be committed by the formula/scheduler path and materialized through [`SpillEngine.applySpill`](../../packages/core/src/SpillEngine.ts#L84), which tracks the anchor and spill children and reports blocked spills. The binder reads the committed anchor cache as its array value. It does not create spill cells, change the one-based spill anchor, or bypass `#SPILL!` checks.

## 7. Boundary with CS-002D4.5

The binder is a resolver, not a scheduler. It performs no recursive evaluation and owns no dependency graph, dirty propagation, topological ordering, SCC/cycle analysis, transaction queue, or recompute generation. D4.5 must provide a workbook-wide graph/scheduler that:

1. extracts local and qualified typed precedents without confusing equal row/column coordinates on different sheets;
2. orders precedent formulas before dependents and commits each result before downstream binder reads;
3. keys active evaluation and cycle diagnostics with workbook-scoped sheet identity plus address;
4. commits deterministic `#CIRC!` values under the selected iteration-disabled cycle policy and propagates them through binder reads; and
5. coordinates snapshot restore, mutation invalidation, and transaction boundaries under the CS-001C contract.

Until D4.5 exists, this contract does not claim that cross-sheet dependency chains or cross-sheet cycles are scheduled correctly. A binder read of a formula cell returns its current committed cache, even if stale; it must not compensate by recursively evaluating the formula.

## 8. Acceptance matrix for implementation work

These are design gates for later implementation and are not test results from this ticket.

| Scenario | Expected contract result |
| --- | --- |
| Local-only parity | Existing standalone and workbook-owned local formulas preserve current results, blank behavior, errors, and array results. |
| Qualified cell (`=Data!A1`) | Resolves by case-insensitive display name to that sheet's bound ID and returns the committed cache. |
| Qualified range (`=SUM(Data!A1:B3)`) | Resolves both endpoints to one sheet ID, preserves 2D row/column shape and blank cells. |
| Local range | Retains existing local range shape and aggregation behavior. |
| Quoted sheet name with escaped apostrophe (`='Owner''s Data'!$A$1`) | Decodes the name for lookup, preserves raw source/absolute markers, and resolves to the correct ID. |
| Rename after formula binding | Existing formula continues to target the same ID; display-name directory reflects rename. Formula text rendering remains source-preserving unless a separate rewrite policy is approved. |
| Missing/deleted sheet | Valid qualified reference yields `#REF!`, not `#NAME?` and not a different sheet's value. |
| Stale construction ID after adoption (O1) | Lookup fails and formula yields `#REF!`; no silent forwarding to the adopted worksheet. |
| Invalid coordinate / maximum bounds | Valid XFD1048576 is accepted; zero and coordinates beyond Excel bounds yield `#REF!` and create no valid graph edge. |
| Self-reference | Binder returns the current committed cache; scheduler's cycle policy commits `#CIRC!` when iteration is disabled. Binder does not recurse. |
| Local-to-cross-sheet chain | Precedent sheet formula is committed before dependent local formula reads it; binder returns the committed value. |
| Cross-sheet cycle | Workbook graph detects the SCC and commits deterministic `#CIRC!`; no evaluator recursion overflow. |
| Error precedent | Existing spreadsheet error propagates unchanged through qualified cell and range reads. |
| Array-valued precedent | 1D/2D array remains typed and spill materialization follows existing spill rules. |
| Lazy precedent / lazy function branch | Thunk remains unforced until consumed; a skipped branch does not read/evaluate it. |
| Entity-valued precedent | Entity survives binding and member access uses the existing entity path without recursive formula evaluation. |
| `ISFORMULA` / `FORMULATEXT` qualified operand | Inspect formula metadata at the bound worksheet/address; do not inspect only the current sheet or infer from cached result. |
| Snapshot restore | Restored workbook retains persisted IDs per D4.1 and rebinds references; graph/cache/subscription reconstruction is verified by D4.4–D4.6 gates. |
| Standalone compatibility | With no binder, unqualified references continue to use existing local Worksheet evaluation. |

## 9. Non-goals and next dependency

This contract does not implement or design cross-sheet scheduling, workbook manifest serialization, transaction semantics, migration tooling, import remapping mechanics, formula editing/copy-fill translation, or UI behavior. INDIRECT/OFFSET, whole-row/whole-column, 3D references, external workbooks, named ranges, and structured references remain out of scope under the parent specification.
