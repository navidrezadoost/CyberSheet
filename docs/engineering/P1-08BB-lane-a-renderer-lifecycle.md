## Cleanup implications

The explicit successful-instance disposal path is at `CanvasRenderer.ts:620–654`. It marks the renderer disposed, cancels pending animation frames and the resize timer, disconnects the resize observer, removes canvas/window/document listeners (`removeEventListeners`, lines 4131–4143), disposes the Worksheet subscription, terminates an internally created formula worker, unsubscribes from the drawing layer, and removes the canvas.

That path is only callable when a `CanvasRenderer` instance has been returned. The constructor has no surrounding `try`/`catch` or `finally` that performs equivalent rollback. Consequently, failures after attachment can leave the canvas and previously installed registrations without a caller-visible renderer handle. This is a source-level construction asymmetry, not proof that a particular observer/listener is leaked in every runtime: the exact side effects depend on where the throw occurs and on the collaborator that throws. No source contract inspected here promises constructor-failure rollback or disposal of the caller's Workbook.

## Lane conclusion

The source supports a focused characterization test against the actual `CanvasRenderer`: inject a throwing `drawingLayer.on` implementation through the existing public `drawingLayer` option, assert that construction throws and the container retains the attached canvas, and inspect listener/observer cleanup only through explicit test instrumentation if the test can do so reliably. This is a real-renderer path, not a constructor mock. It establishes the observable post-attachment boundary; it does not prove a renderer can be disposed after failed construction, nor does it establish browser painting or complete resource disposal. A separate pre-allocation test can use invalid view/options, and a detached-canvas test can instrument `getContext`, but neither characterizes cleanup after attachment.

Whether to add/run those tests is an integration decision for the coordinator. This lane made no test or production change.
