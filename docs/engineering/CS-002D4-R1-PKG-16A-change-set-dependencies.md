## Recommended review/integration order

1. Review the change inventory and resolve provenance for the 52 production-source paths; map each source hunk to an approved package record and one or more tests.
2. Review test infrastructure as a self-contained resolver/configuration unit, with the PKG-08A compatibility test and workspace command matrix.
3. Review the seven-operation transaction source/test unit separately from formula grammar and Pivot lifecycle; retain explicit shared-file conflicts for `workbook.ts`, `worksheet.ts`, and `DependencyGraph.ts`.
4. Review formula and standalone Pivot units against their current accepted contracts. Do not implement F1/F2/F3 without the formula-owner decision, and do not merge standalone Pivot evidence as Workbook support.
5. Keep the React/framework/renderer changes package-scoped, with their own package tests/typechecks and Core API dependency record.
6. Preserve reports, raw outputs, protected sidecars, and existing artifacts as review evidence. No historical baseline recapture, broad staging, merge, or cleanup is authorized.
