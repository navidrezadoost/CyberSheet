# P1-08AY Lane C — Examples and integrations review

## Method and limits

This review covers only the 25 fixed `C-Examples-Integrations` selections in `P1-08AY-selection-inventory.tsv`, ranks 1–25. Identity is the exact `(record_type, record_key, path)` tuple. For each tuple I inspected the selected source context in the current checkout, its downstream use or owning initializer, and the closest existing test evidence. The selection inventory is a frozen input; several Vue/Svelte/Angular source anchors have since drifted, and the table points at current source while preserving the selected anchor context in the selection file.

Labels describe the evidence review, not ledger dispositions: `reviewed` means occurrence-specific evidence exists and is cited; `evidence-insufficient` means source was inspected but no directly relevant test establishes the selected behavior; `owner-blocked` means the selected integration depends on a presently gated owner operation/slice. No source, test, ledger, disposition, or register was changed. No test suite was run. References below are existing tests and checkpoint evidence only. Similar-looking tests are not treated as covering these exact occurrences.

The exact three React viewer flow keys at ranks 1–3 were already occurrence-specifically reviewed in the reconciliation checkpoint. The Vue/Svelte/Angular selected anchors for old `new Workbook()`/`addSheet()`/row-write code are stale: current code uses `Workbook.create()` and explicit gates; this review records the current code and does not claim the old anchors still execute.
