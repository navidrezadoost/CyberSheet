## Current Workbook transaction surface

`WorkbookMutationPort` and `WorkbookTransactionContext` expose exactly seven kinds in [workbook-access-types.ts](../../packages/core/src/workbook-access-types.ts#L27-L52), implemented by the discriminated operation union and application switch in [workbook.ts](../../packages/core/src/workbook.ts#L58-L70) and [workbook.ts](../../packages/core/src/workbook.ts#L605-L644):

| Operation | Primary state / owner | Side effects and publication | Coverage boundary |
| --- | --- | --- | --- |
| `setCellValue` | CellStore value in a Worksheet | Formula dependency/recalculation effects where applicable; buffered `cell-changed`, then existing Cell bridge | Covered by PKG-01K/02A–02C for the tested cell-write slice. Not a proof of every volatile or derived-state path. |
| `setCellFormula` | CellStore formula/value and dependency graph | Formula registration/replacement and value/formula notifications; buffered after commit | Tested within the seven-operation slice; volatile registration and every formula-result lifecycle are not thereby globally closed. |
| `clearCellContent` | CellStore content and dependent graph edges | Clears cell content and graph effects; event is buffered | Tested in mixed Journal/Snapshot paths; not general structural deletion. |
| `clearCellFormula` | CellStore formula and graph edges | Formula removal; existing Workbook formula bridge emits only according to its established mapping | Tested in mixed paths; event semantics for all formula result cases remain outside a global closure. |
| `setCellStyle` | CellStore style plus Workbook `StyleCache` references | Provisional style interning/refcount settlement; buffered style event and existing bridge | Tested in mixed and failure cases. Does not cover row/column styles or conditional formatting. |
| `setRowHeight` | Worksheet sparse `#rowHeights` map | Generic Worksheet `sheet-mutated` and typed Workbook `row-height-change`, staged after commit | Operation-specific closure: PKG-02A. Exact sparse presence/default rollback. |
| `setColumnWidth` | Worksheet sparse `#colWidths` map | Generic Worksheet `sheet-mutated` and typed Workbook `column-width-change`, staged after commit | Operation-specific closure: PKG-02B. Exact sparse presence/default rollback. |

The Workbook preflights staged operations, captures Journal or comparison Snapshot state, applies under Worksheet mutation capabilities, settles batches, marks the commit point, and only then publishes buffered events ([workbook.ts](../../packages/core/src/workbook.ts#L535-L568), [workbook.ts](../../packages/core/src/workbook.ts#L581-L679), [workbook.ts](../../packages/core/src/workbook.ts#L739-L767)). PKG-02C describes the Snapshot comparison state as the cell-write slice, not a complete Worksheet snapshot. Rollback guarantees must remain limited to exercised state and failure cuts. Existing shared FIFO self-await remains a separate limitation.

## Frozen D2-11 family reconciliation

D2-11 names formula dependency graph, volatile state, row/column dimensions, visibility, comments, drawings, conditional formatting, Pivot accumulators/snapshots, external host persistence, and undo history. The mapping below preserves those family boundaries; it does not promote ledger records or close the global contract.

| Frozen family | Current owner and actual entrypoints | Current transaction evidence / side effects | Status and dependency |
| --- | --- | --- | --- |
| Formula dependency graph | Worksheet `#dag`; cell/formula methods, `registerDependencies`, volatile registration/recalculation methods in `worksheet.ts` | The five cell-write operations have Journal graph mutation handling and Snapshot graph capture in the tested slice. Formula writes can also touch volatile/recalculation coordination; not every mutation path is represented by those five operations. | **Partly covered** for the seven-operation slice; volatile and broader recalculation effects remain open. Depends on formula-engine and graph correctness, not D5-05. |
| Volatile state | Worksheet recalculation coordinator / DAG volatile registrations; `registerVolatile`, `clearVolatile`, `flushVolatiles`, formula apply/recalc methods | Formula replacement and calculation may alter registrations/status beyond a simple cell before-image. Existing cell-write tests do not inventory all recalculation scheduler state. | **Open.** Requires a precise operation-specific lifecycle and scheduler-state before-image. |
| Row/column dimensions | Worksheet `#rowHeights` / `#colWidths`; `setRowHeight`, `setColumnWidth` | Generic `sheet-mutated`; typed Workbook dimension events. Sparse map presence is significant. | **Closed only for the two operation-specific slices**, PKG-02A/B. Bulk dimensions, AutoFit, and structural remapping remain outside those closures. |
| Visibility | `VisibilityStoreV1` row/column `Set`s; Worksheet `hideRow/showRow/hideCol/showCol` ([worksheet.ts](../../packages/core/src/worksheet.ts#L2799-L2839), [VisibilityStore.ts](../../packages/core/src/storage/VisibilityStore.ts#L90-L145)) | Idempotent membership mutation; emits `row-hidden`/`row-shown` or `col-hidden`/`col-shown`, then `sheet-mutated`. Hidden rows/columns affect find/iteration and renderer layout, but not cell reads. Snapshots include hidden rows/columns; binary codec has a visibility section. | **Open.** Distinct owner store not covered by the current Journal/Snapshot transaction slice. Four transition directions and exact Set membership require characterization. Typed Workbook/ Application forwarding authority is not defined for these events. |
| Comments | CellRecord `comments`; `addComment`, `updateComment`, `deleteComment` ([worksheet.ts](../../packages/core/src/worksheet.ts#L2990-L3093)) | Add/update/delete events; comment add/edit/delete names already have Worksheet-to-Workbook bridge mappings in [eventBridge.ts](../../packages/core/src/eventBridge.ts#L14-L25), [eventBridge.ts](../../packages/core/src/eventBridge.ts#L82-L109). Delete can remove a threaded subtree. `CellRecord` is covered by the cell-write Journal, but its current before-image is shallow; add mutates the comments array in place, update replaces an element in place, while delete replaces the array. | **Open.** Delete of a single addressed comment is the smallest candidate. Broader add/update/thread semantics need separate state and ID/timestamp contract evidence. Existing Workbook comment event names reduce schema expansion, but D5-01 remains pending. |
| Drawings | Worksheet DrawingLayer and image/object state; `getDrawingLayer`, `insertImage`, `deleteImage`, adoption clone logic in `worksheet.ts` | Adoption explicitly clones drawing state; renderer subscribes to layer changes. The cell-write Journal/Snapshot captures neither object graph nor loaded image resources. | **Open / high complexity.** Exact rollback must include layer objects, change notifications, and renderer resource ownership. Requires lifecycle/resource contract work; not a small cell operation. |
| Conditional formatting | Worksheet `#conditionalRules`; `setConditionalFormattingRules`, `addConditionalFormattingRule`, `clearConditionalFormatting` ([worksheet.ts](../../packages/core/src/worksheet.ts#L1592-L1645)) | Current mutators replace or mutate a separate rules array and emit `sheet-mutated`. Renderer and Core evaluators consume the rules; adoption clones rules. Current transaction snapshot does not include the rules array or its nested rule data. | **Open.** A narrow replace/clear operation could be bounded, but needs detached nested before-images and rule-evaluation/render invalidation tests. No typed Workbook event route exists. |
| Pivot accumulators / snapshots | Workbook pivot registry, dependency index, recompute engine, group-state store, snapshot store; source mutation observers and public pivot config/query routes in `workbook.ts` | Source writes can invalidate pivots; partial recomputation mutates group accumulators and then publishes snapshots. PKG-08X/AA recovery work bounds selected failure sequences but does not compose Pivot state into the Workbook mutation transaction. | **Open / high complexity.** Requires D3 policy, source-index ownership, group-state and snapshot rollback/recovery integration. Do not equate a safe pivot refresh fallback with D2 source-transaction atomicity. |
| External host persistence | SnapshotCodec and package IO/XLSX paths, distinct from in-memory Worksheet state | Row/column dimension closures explicitly did not expand binary persistence; some object snapshots and binary codec sections differ. A Workbook transaction cannot by itself roll back a file replacement or host checkpoint. | **Open and boundary-dependent.** Requires a separate host persistence/checkpoint contract and durable failure model; not a candidate for the next Core mutation. |
| Undo history | Standalone `CommandManager`, command classes, React command wrappers; Workbook mutation port has no owner-backed history interface | Existing Workbook operations provide FIFO transaction and rollback, not undo/redo history. Standalone command history captures operation-specific snapshots and may be unavailable for owner-backed sheets. | **Open.** Requires decision whether history is a transaction side effect or a separate command layer, plus event/replay semantics. Not included implicitly in any seven-operation closure. |

### Cross-cutting families outside the enumerated list

Structural row/column insertion/deletion also remaps cells, dependency references, dimensions, visibility, merges, filters, and possibly comments/drawings/Pivot source ranges. It is substantially broader than the dimension setters and should not be folded into “row/column dimensions.” This map records it as a cross-family dependency for later review, not as a changed frozen D2-11 row.

## Reconciliation outcome

Seven operations remain the complete current Workbook transaction API. PKG-02A closes only row height; PKG-02B closes only column width; PKG-02C verifies integration for those seven. The remaining D2-11 families are not inferred closed by shared implementation mechanics. Recommended next bounded family is a **single-comment delete transaction**; see [operation priorities](CS-002D4-R1-PKG-03B-operation-priorities.md) and [design](CS-002D4-R1-PKG-03B-next-operation-design.md).
