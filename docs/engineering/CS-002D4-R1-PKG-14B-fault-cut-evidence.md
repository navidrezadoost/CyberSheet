## Interpretation of the new verified suite

The new suite passed all 30 cases and deliberately separates pre-first-apply failure, post-first-operation rollback, and post-commit publication disposal. The first two cases compare full `Worksheet.extractSnapshot()` state from the underlying test fixture, including explicit dimension maps, cells and formula graph serialization. It also checks that no queued Worksheet commit event escapes and that a successful restore leaves health `healthy`. Those exceptions are injected only using the existing internal Workbook mutation hooks; no public failure API is introduced. Raw output: `CS-002D4-R1-PKG-14D-focused-verified-jest-output.txt`.

The publication case has no synthetic fault hook: a real observer calls the public Workbook `dispose()` method after the commit point. It expects all state writes to persist while subsequent notifications stop. It does not treat observer disposal as rollback, does not assert cross-surface callback completion ordering, and does not inspect browser/rendering resources.

## Still-uncovered cuts

1. Every possible internal subphase of formula graph mutation is not faulted for every formula operation and strategy. Existing hooks name dependency removal/registration, watcher registration, formula-node registration, dirty propagation, and volatile-state changes, but the package evidence does not constitute a full Cartesian matrix over operation × phase × graph shape.
2. StyleCache reference counts have no public inspection API. Tests observe cell/style snapshots and recovery behavior, while source inspection supports ref ownership; exact private count equivalence is not directly asserted.
3. The new tests do not inject a failure during the callback body itself, an allocation failure, process termination, or host-level resource failure. The tested `beforeApplyOperation` is a supported internal simulation seam.
4. Application-level event forwarding is not present as an authorized surface. D5-05 schema/authority and D5-01 cross-level completion ordering remain separate decisions.
5. Transaction observers cannot prove visual repaint completion. Canvas scheduling/painting is outside Core transaction publication.
6. Rollback after a listener begins is not a supported property: listeners run only after commit. Post-commit observer exceptions/disposal are publication behavior, not rollback cuts.
7. Pivot invalidation cannot be exercised through a supported Workbook-owned registry/lifecycle route; observer-driven invalidation evidence is limited to source and standalone/component tests.
