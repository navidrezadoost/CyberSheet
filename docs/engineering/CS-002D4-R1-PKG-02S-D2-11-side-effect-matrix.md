**Status:** inventory and rollback design; not implemented
**Authority:** D2-11 remains globally unresolved; this matrix covers only this candidate operation.

## Journal extension design

Extend the internal Workbook cell-write journal (or a deliberately renamed/generalized Worksheet mutation journal during implementation) with `rowHeights: Map<number, { present: boolean; heightPx?: number }>` alongside the existing sparse cell map and dependency-graph journal. A row-height before-image is captured once, before the first assignment to that row in the transaction. Repeated writes update the primary map but do not replace the original before-image. A multi-row transaction retains one entry per touched row, not a copy of all Worksheet state. A multi-Worksheet transaction has an independent sparse journal per touched Worksheet; rollback traverses Worksheets in reverse participation order.

The current Journal captures state at the start of a batch while operation arguments are staged. This feature should preserve that scheduling model: before-images are captured after validation and before any operation is applied. The Worksheet journal must distinguish missing from explicit default-valued entries. It must not reuse `getRowHeight` as the sole restoration source.

The Snapshot comparison path is intentionally different: capture all explicit row-height entries into its existing detached per-Worksheet comparison state, then restore the map as part of snapshot rollback. It must not call the Journal restore helper. Equivalence means equal rowCount/colCount, equal ordered explicit row-height entries (including absent-vs-explicit-20), equal emitted committed events, equal final `getRowHeight` results, and equal mutation health across Journal and Snapshot for the row-height scenarios. Snapshot remains internally selectable; production default remains Journal.

## Failure points and recovery

Required internal fault seams are: before primary map write; immediately after a selected row-height map write; while restoring a row-height before-image; and after a rollback restoration but before pending-batch discard. Reuse existing internal Workbook mutation test-hook infrastructure where it can express the phase; otherwise add a test-only, non-barrel-exported hook in the separately authorized implementation package. No public failure-injection API.

Before any primary write, failure leaves row maps unchanged and produces no committed event. After one or more writes but before commit, failure restores exact sparse-map state and publishes no event. A restoration failure makes state uncertain, produces `WorkbookMutationRollbackError` with both error classes, and sets health to `recovery-required`; subsequent queued writes reject. Failure after the publication point is not rollback: state remains committed and observer error handling is isolated under D2-08/D2-09.

This is a bounded operation design, not proof that all D2-11 state families are inventoried or that the current generic Worksheet transaction is atomic for arbitrary operations.
